## introduction

`shm_msgs` provides fixed-size ROS 2 message definitions and a set of tools for
shared-memory (zero-copy) image and H.265 video transport, along with offline
rosbag2 processing utilities. Fixed-size messages are required by the loaned
message API so that true zero-copy inter-process transport is possible.

## message definitions

All messages are generated by `rosidl` and live under `msg/`.

| message                | description                                                       |
|------------------------|-------------------------------------------------------------------|
| `shm_msgs/String`      | fixed-size char[256] string                                       |
| `shm_msgs/Header`      | timestamp + frame_id (uses `shm_msgs/String`)                     |
| `Image8k/512k/1m/2m/4m/6m/8m` | fixed-size uncompressed image (data `[N]`)               |
| `CompressedVideo`      | one Annex-B H.265 chunk + frame metadata                          |
| `DynamicObject`        | dynamic obstacle (uses `geometry_msgs`)                          |
| `StaticObject`         | static obstacle (uses `geometry_msgs`)                           |
| `Obstacle`             | obstacle result list (dynamic + static)                          |
| `Pallet`/`PalletData`  | pallet detection result + item                                   |
| `Slot`/`SlotData`      | slot detection result + item                                      |
| `DrivableArea`         | drivable area (freespace, curbs, occupancy)                      |
| `LocalizationInfo`     | localization message (pose, attitude, speed, std)                 |
| `ImageFrame`           | camera frame (sensor id, data_ptr/image_data)                    |
| `LidarFrame`           | lidar frame (point cloud array)                                   |
| `CompressedImageFrame` | encoded image (format + data)                                     |
| `EulerAngle`/`SensorID`/`PointCloudData`/`Polygon`/`PolyLine`/`FreeSpace`/`Curb`/`Occupancy` | supporting sub-messages |

Headers under `include/shm_msgs/` provide helpers around these messages:
`opencv_conversions.hpp` (shm Image <-> cv::Mat), `array_helper.hpp`
(shm String <-> std::string), `image_encodings.hpp`, `fill_image.hpp` and
`rgb_colors.hpp`. The `shm_msgs_image` library (built from `lib/`) implements
the OpenCV conversions and RGB helpers.

## online tools

ROS 2 runtime executables that bridge/encode/decode shm messages.

| tool                              | description                                                                  |
|-----------------------------------|------------------------------------------------------------------------------|
| `shm_image{8k,512k,1m,2m,4m,6m,8m}_bridge` | bridge `shm_msgs::msg::Image*` -> `sensor_msgs::msg::Image`        |
| `shm_image6m_bridge_6ch`          | 6-channel version of the bridge                                              |
| `shm_image6m_bridge_6ch_compressed` | 6-channel `Image6m` -> `sensor_msgs::CompressedImage` (OpenCV, no cv_bridge) |
| `shm_image6m_subscriber_6ch`      | 6-channel subscriber reference                                               |
| `shm_image6m_consumer_6ch`        | 6-channel consumer reference (teleop streaming)                              |
| `shm_image6m_h265_encoder_6ch`    | 6-channel hardware H.265 encoder (`Image6m` -> `CompressedVideo`), dlopen `libvideoenc.so` |
| `shm_image6m_h265_encoder_6ch_allfps` | all-fps variant: encodes every input frame with the original timestamp   |
| `h265_decoder_6ch`                | 6-channel online H.265 decoder (`CompressedVideo` -> `sensor_msgs/Image` bgr8, FFmpeg) |

Launch files for the bridge/subscriber/decoder tools are under `launch/`.

## offline tools

These read a rosbag2 bag (db3/mcap) directly via `rosbag2_cpp` and do not need
`ros2 bag play`.

### h265_decoder_readfile

Reads a bag containing `shm_msgs/msg/CompressedVideo` (H.265), decodes to
`sensor_msgs/msg/Image` (bgr8) and writes a new bag.

```sh
# mcap input -> db3 output
ros2 run shm_msgs h265_decoder_readfile \
  --bag /path/to/input.mcap --out /path/to/output_bag --out-storage-id sqlite3

# db3 input -> mcap output
ros2 run shm_msgs h265_decoder_readfile \
  --bag /path/to/input_bag_dir --out /path/to/out
```

### bag_to_obstacle_input

Reads `shm_msgs/msg/Image6m` (4 fisheye) + `sensor_msgs/msg/PointCloud2`
(LiDAR), dumping images and PCD files named by timestamp into
`<out>/<bag_name>_clip/`.

```sh
# flat mode: dump every frame by timestamp
ros2 run shm_msgs bag_to_obstacle_input --bag <bag> --out <dir>

# sync mode: keep only aligned frames (4 png + 1 pcd per lidar frame)
ros2 run shm_msgs bag_to_obstacle_input --bag <bag> --out <dir> --sync --sync-tolerance-ms 50
```

### mergelidar_h265_clip

Fusion tool: reads a bag with H.265 `CompressedVideo` (4 fisheye) +
`PointCloud2` (LiDAR), decodes H.265 to BGR, then matches 4 camera frames to
each lidar frame by timestamp and writes aligned clips. Suited for
`/camera/fisheye_*/h265` + `/LidarDataInv` bags.

```sh
# default sync mode
ros2 run shm_msgs mergelidar_h265_clip \
  --bag /path/to/rosbag2_xxx --out /path/to/clip_output

# tune tolerance and decoder threads
ros2 run shm_msgs mergelidar_h265_clip \
  --bag <bag_or_dir> --out <dir> --sync-tolerance-ms 30 --decoder-threads 4

# flat mode: no matching, dump all frames
ros2 run shm_msgs mergelidar_h265_clip --bag <bag> --out <dir> --flat

# process every bag under a directory
ros2 run shm_msgs mergelidar_h265_clip --bag /path/to/bags_dir --out /path/to/out
```

Common options:

| option               | default        | description                                        |
|----------------------|----------------|----------------------------------------------------|
| `--bag`              | required       | input bag or a directory of bags                   |
| `--out`              | required       | output dir, results in `<out>/<bag>_clip/`         |
| `--lidar-topic`     | `/LidarDataInv` | LiDAR point cloud topic                           |
| `--camera-topics`   | 4x h265        | comma-separated camera topics override            |
| `--sync-tolerance-ms` | 50           | timestamp match tolerance (ms)                     |
| `--decoder-threads`  | 1              | FFmpeg decoder threads per stream                  |
| `--image-ext`        | png            | output image format (png/jpg)                      |
| `--max-frames`       | 0              | max frames per stream, 0 = unlimited               |
| `--flat`             | -              | skip matching, dump all frames                     |
| `--storage-id`       | auto           | input storage format (mcap/sqlite3)                |

### extract_h265_from_bag.py

Extracts Annex-B H.265 streams and a per-stream timestamp CSV from a rosbag2 bag.

```sh
ros2 run shm_msgs extract_h265_from_bag.py <bag_dir> <output_dir>
```
